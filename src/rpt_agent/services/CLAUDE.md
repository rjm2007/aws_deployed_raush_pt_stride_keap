# services — business workflows and provider clients

Routes and the worker call into these. Each workflow owns its SQL and runs inside the caller's
`transaction()` connection unless noted.

## Workflows

| File | What it owns |
| --- | --- |
| `lead_actions.py` | Google Sheet commands from n8n: `execute_lead_action()` (start / restart / DNC / booked, idempotent on request ID via `lead_action_requests`) and `sync_sheet_lead()` (profile sync; a name change is flagged for review with old/new name, a phone change closes the lead at once; with `sheet_rules` (direct mode, 2026-10-25) Location / Case / Date Of Birth are reviewed the same way (`_detail_changes`, kept values via `_kept_value` / `spend_kept_values`) and an Email change is applied and logged "Email changed in Google Sheet"). `_restart_cadence` has a 10-min cooldown and refuses while a step is due soon (`outreach_due_soon`, `worker.next_due_soon`: sendable now, or due within 5 min / 30 s for TEST_MODE test leads; 2026-10-26, also on the board's move to New); with `sheet_rules` it also counts review-card restarts and refuses a lead in review (`restart_needs_review`), booked (`restart_booked`) or closed by a decision (`restart_closed`: front desk, newer row, declined). n8n mode passes no `sheet_rules`: unchanged. |
| `lead_status.py` | Lead/call state machine (locks the lead before the outreach event, like the booking): `apply_call_outcome()`, `report_lead_status()`, callbacks clamped to business hours, explicit opt-outs, `mark_booked()`, status history. |
| `delivery.py` | Settles provider results: Vapi end-of-call reports (`process_vapi_end_report`, transcripts, structured outcome; a summary's `declined` needs the patient's own refusal, `REFUSAL_PHRASES`, else `no_answer`, 2026-10-27; a summary's `booked` with no appointment flags `booking_hung_up`, "Patient asked to book, then hung up"), Twilio delivery status, outbox processing (confirmation SMS, Keap handoff), reprocessing of failed webhooks. |
| `hang_up_booking.py` | Demo booking engine only (owner, 2026-10-27): `book_confirmed_time_after_hang_up`, called from the end-of-call report. The patient's first reply to Elliot's "So that's ... Shall I book it?" (wording variants tolerated) is a plain yes (farewells dropped) and they hung up before a booking was made: books the one offered slot it names via `slot_booking.book_slot`; a yes it cannot book safely (cut-short question, yes with other words, slot unclear, no last name, birthday not confirmed, TAKEN, ...) goes to Needs Review (`booking_said_yes`, book by hand). "Already booked" comes from the database (appointment booking / scheduled / unknown), never from the report's tool calls; booking disabled = no-op. |
| `booking.py` | `BookingService`: Stride availability and appointment creation, patient/case creation, idempotency, confirmation SMS. Gated by `practice_settings.stride_booking_enabled`. |
| `slot_booking.py` | Booking engine for the voice agent: `find_slots()` (lead → location → case type → clinicians → 3 nearest cached slots, remembered per call; default searches look 31 days ahead, a named date / `next_month` / `specific_month` up to 90; past that "too far ahead" + the nearest times) and `book_slot()` (hold → live re-check → patient → case → appointment). A booking not made on a voice call (FOLLOW_UP, PATIENT_EXISTS, UNCONFIRMED; TAKEN only after an IN_PROGRESS reply, `in_progress_reply_at`) flags the lead (Booking group) and the agent says the front desk will reach out, never a text; a request meeting the patient's running attempt waits up to `IN_PROGRESS_WAIT_SECONDS` for it before answering (2026-10-26). See `docs/BOOKING_ENGINE.md`. |
| `booking_check.py` | Second look at an unclear voice booking (`appointments.state='unknown'`), run by the booking-worker: Stride's imported files (found -> scheduled + lead booked, review closed "confirmed in Stride"), then Stride's openings read-only (time still open -> failed, slot open again, review "booking did not go through"); backoff 1-29 min, then files only. Never writes to Stride. |
| `availability_sync.py` | Refreshes the `availability_slots` cache from Stride per location + visit length: `BOOKING_CACHE_DAYS` (90) in chunks of at most 31 days (Stride's limit), chunk 0 every `BOOKING_SYNC_SECONDS`, later chunks every `BOOKING_FAR_SYNC_SECONDS` / on a new day (`due_chunks`); `booking_now()` honours `BOOKING_TODAY_OVERRIDE`. |
| `lead_stage.py` | `stage_of()` (board column, used by `routes/dashboard.py` as `_stage`; `STAGE_SQL` is the same rule as one SQL expression, parity tested for every combination in `tests/test_lead_list_integration.py`, change both together) and `sheet_lead_status()` (the Sheet's Lead Status mirrors the column: New / In cadence / Paused / Needs Review / Booked / Do not outreach / Closed). |
| `lead_list.py` | Leads page in the database (2026-10-28): `list_page` (leads + unlinked Stride patients newest first, filters source / stage / owner / location / search on name, email, phone digits; totals per source), `board_page` (per column next ids + real totals), `stride_rows` / `stride_patient` (view-only Stride rows: Booked with a visit on the books, else "No upcoming visit" / "No visits"). Source = where the row started (`leads.source_system='google_sheets'` stays Sheet once booked). |
| `review.py` | `skip_remaining_planned` / `restore_pause_skipped` (pause/resume mechanics), `flag_lead_for_review` + `record_review` (every flag gets a `lead_reviews` row with a code), `hand_over_number` (one active lead per phone; new lead inherits opt-outs; `reason=REPLACED_REASON` for a new lead, `RESTARTED_REASON` "replaced: another lead with this phone was restarted" on every path that starts an existing lead again: Sheet Restart, board New / In cadence, review restart / resume, unblock, Resume; Sheet text `SHEET_RESTARTED`, 2026-10-26; the replaced lead gets status `closed_no_response` unless already closed, never a booked one; Keap keeps it Pending, not gave up). |
| `lead_review.py` | Review codes → groups → choices, plain reasons (Twilio codes), `describe()` card, `options_preview()` (confirm pop-up), `resolve_review()` (resume/close/restart; restart choices (`RESTART_CHOICES`, 2026-10-25) on name, details, text, call, technical, other and appointment cards, never while another review is open, with the 10-min cooldown (`last_review_restart`); "keep old name" queues a `name_kept`, "keep old <field>" a `value_kept` Sheet update that writes the old value back into the row; `choice_label` / `sheet_resolved_text` name the field for the Details group), `close_for_phone_change()`, Sheet review texts. Demo-only groups: Appointment (Stride cancel/no-show) and Booking (agent could not confirm; front desk only). |
| `number_block.py` | Dashboard Do not contact switch: `block_number()` (same effect as the Sheet command) and `unblock_number()` (admin only; must choose `continue` or `restart`, clears opt-outs on the number, tells the Sheet). |
| `stride_import.py` | Parses one Stride export file and applies it to `stride_*` tables: Upsert/Delete tombstones, newer-wins on Modified Date Time, appointment Deletes matched by case + start, PHI-free row issues. |
| `stride_leads.py` | Links Stride patients to leads (name + DOB, or name + phone), marks a lead booked when Stride shows a future appointment, flags it for review when that booking is cancelled. Recomputed each tick. |
| `appointment_views.py` | Read-only booking records for the dashboard (calendar, lead booking card, home Next appointments, booked board cards, assistant context): merges our `appointments` with `stride_appointments` (Stride wins once imported), normalises Stride statuses, tags each visit Elliot / Sheet lead / Stride only, and finds the call moment for Elliot bookings. Calendar fields (2026-10-26): `source` elliot/sheet/stride, `approval` (ours not yet in Stride's export = `waiting`; Elliot books as pending and the export has no pending status), `stride_status`, `visit_kind`, `patient_name` "Last, First", `clinician` with role; one display name per clinician (ours when known); `waiting_records()` (approval list, upcoming never dropped) and `open_slots()` (cached open Stride slots per clinician, clinic and day, with `location_id` / `location`, each slot once per clinic; nothing estimated). |
| `google_sheet.py` | Google Sheet access (gspread, service account): whole-tab read, columns by header text, queued cell writes that re-check each row's identity (Lead ID, Action Request ID, Name, Phone) just before writing; `set(expect=...)` also skips one cell staff changed since the read (Name write-back). |
| `sheet_direct.py` | Direct Sheet sync (replaces the n8n workflows): command rules and labels, claim → `execute_lead_action`, stuck-row recovery with the same request ID, profile sync by fingerprint (`sheet_row_state`), snapshot → row. On a lead in review Booked / Do Not Contact run; a Restart goes to the backend with `sheet_rules` and is refused at once (review, booked, closed: `REVIEW_REFUSED` / `BOOKED_REFUSED` / `CLOSED_REFUSED`), Action empties (owner, 2026-10-25; the old parked Restart is gone, a row still holding one is emptied with the refusal, `_legacy_waiting`). Refusals the worker makes itself (Start on a linked row, invalid linked row, old waiting Restart) are noted in the lead's Activity (`note_refusal`). Action (owner, 2026-10-25): staff pick a command, it runs, the cell empties: once handled (ran, refused, invalid row, Start on a linked row) `_clear_action` empties Action (only if it still holds that command: `expect`) and the Action Request ID in the same write as the result, so a command in Action is always new and staff re-pick it to run it again; the worker never fills Action. Commands match the drop-down values exactly (only extra spaces forgiven); any other text in Action, also another case, gets `UNKNOWN_COMMAND` ("Error: action must be chosen from the drop-down.") once settled and is emptied the same way, nothing runs (`unknown_command`, 2026-10-26). Refusals staff can act on get their own text (`_refusal_text`: `outreach_unresolved`, `restart_too_soon` and `outreach_due_soon` with `retry_at`, time via `pt_clock`). Rows from before 2026-10-25: `old_commands` / `retire_old` empty an already handled command (request with the same action finished, or the old status rules `_old_rules_run` would not run it) without running it, and drop the old "clear this cell" words. A Restart is never run while the lead has an open review in the database (backend check), even with Outcome Status cleared. A `name` / `kept` in the snapshot (keep old name / value) goes into the cell only over the reviewed new value (`_restore_name`, `_restore_values`), with the fingerprint updated if the row was otherwise in sync. A wrong email is only a warning (`row_email`, 2026-10-26): never an error or review, not sent (new lead: no email; edit: the lead keeps its own), Outcome `STARTED_EMAIL_WARNING` / `EMAIL_WARNING`, cleared once fixed. |
| `sheet_sync.py` | Builds the Sheet snapshot (`build_sheet_snapshot`) and enqueues it (`enqueue_sheet_update` → `integration_outbox`). Omits `action_status` unless booked / DNC / completed so n8n keeps the existing cell. `action` / `review_action` (and `DASHBOARD_OUTCOMES`' third value) are for n8n mode only; direct mode ignores them. Reason `board_closed` (board move to Closed) writes Outcome Status "Closed on the dashboard". With reason `name_kept` it adds `name` / `name_replaces`, with `value_kept` a `kept` map (column -> [value on file, value it replaces]) (direct mode only; n8n ignores them). |

## Provider clients

| File | Provider |
| --- | --- |
| `provider_http.py` | `ProviderService` base: bounded timeouts, retries, `ProviderError` classification. All provider clients extend it. |
| `vapi_service.py` | Vapi outbound call creation. |
| `twilio_service.py` | Twilio message send (uses `TWILIO_FROM_NUMBER` from `.env`). |
| `stride_service.py` | Stride HTTP contract (availability `Slot`s, patients, cases, appointments). |
| `keap_service.py` | Signed `appointment.booked.v1` handoff to the Keap team webhook. |

## Notes

- Anything that skips or creates `outreach_events` changes who gets called; add a test in `tests/`.
- Sheet-facing response codes (`*_needs_review`, `restart_too_soon`, `lead_already_exists`, …) are mapped to
  Sheet text by the n8n workflows (n8n mode) and by `sheet_direct.label_result` (direct mode); keep `plan.md`
  in sync when adding one.
- Provider mode (real/mock) is chosen in config; never branch business logic on it.
